# Native gate track

This track changes the elementary gate model. Its counts must be compared within
a named gate set. The saved baseline is a regrouping of the preserved exact14 circuit,
not a discovery of a lower-CNOT circuit or an optimality result.

## Input conventions

`native_gate_check.py` accepts a JSON object with `n` (2 through 8) and a
chronological `gates` list. Wire zero is the most significant bit. Two-wire native
gates use `qubits: [first, second]`; local basis order is `00,01,10,11` with
`first` the more significant local bit even when its global wire index is larger.
CX uses the existing `control` and `target` fields. Existing local gates
`h,x,s,sdg,rx,ry,rz,u3` retain the existing checker conventions, including
`Rk(theta) = exp(-i theta sigma_k/2)` and the existing `u3` matrix.
Native and rotation angles are finite radians or strings such as `"pi/8"`.
No arbitrary matrix gate is accepted.

The gate names and fields are:

| Name | Additional fields | Definition |
|---|---|---|
| `xx_yy` | `qubits`, `a`, `b` | `F(a,b) = exp(i a XX + i b YY)` |
| `iswap` | `qubits` | `F(pi/4,pi/4)` |
| `sqrt_iswap` | `qubits` | `F(pi/8,pi/8)`, positive-i square root |
| `cp` | `qubits`, `theta` | `diag(1,1,1,exp(i theta))` |

Writing `c_-=cos(a-b)`, `s_-=sin(a-b)`, `c_+=cos(a+b)`,
`s_+=sin(a+b)`, the explicit F matrix is

```text
[ c_-     0       0      i s_- ]
[  0     c_+    i s_+      0   ]
[  0    i s_+    c_+       0   ]
[ i s_-   0       0       c_-  ]
```

Thus iSWAP fixes `00,11` and maps `01` to `i*10`, `10` to `i*01`.
The square-root gate has the odd block `(I+i X)/sqrt(2)`. These signs matter:
negative-i hardware conventions need an explicit conversion before comparison.

## Costs and evidence

All-to-all connectivity and free arbitrary single-qubit gates are assumed.
`two_qubit_count` counts every listed two-wire operation, including a syntactically
listed identity such as `F(0,0)`; it does not simplify gates. `two_qubit_depth`
is the greedy dependency depth when disjoint wire operations may run together,
single-qubit gates cost zero, and chronological order on each wire is preserved.
It is not physical pulse duration. `native_family_gate_count` excludes CX;
`cnot_count` counts the CX gates literally present in the native input.

`cnot_compilation_upper_bound` is a constructive bound, not a minimal CNOT
cost: each CX costs one and each supported native gate has a two-CX compilation
with free local gates. `minimum_cnot_cost: null` means unknown, never zero.
For F, reuse the identity in `topology14_exact_matchgate_derivation.md`:
chronological `Rx_c(-pi/2),Rx_t(-pi/2),CX, Rx_c(-2a),Rz_t(-2b),CX,
Rx_c(pi/2),Rx_t(pi/2)`. It covers both fixed exchange gates.
For CP, chronological `Rz_c(theta/2),Rz_t(theta/2),CX,
Rz_t(-theta/2),CX` equals CP up to global phase `exp(-i theta/4)`.
Special cases can cost less; this checker does not claim minimality.

`evaluate` numerically checks every matrix for finiteness/unitarity and tests
`U V_n U†` for diagonality and n-th-root eigenvalues. Optional reference
comparison aligns only one global phase, not an output permutation or eigenbasis
gauge. These are floating-point tests. Existing exact certificates certify the
compiled incumbent; this checker does not extend their domain to native inputs.
The repository also has a separate raw-matchgate certificate, which should be
revalidated before using it as stronger evidence.

## Baseline and reproducibility

`collaboration/native_baseline.json` groups gate ranges 23–30, 31–38, 47–54,
and 55–62 (zero-based inclusive) of
`topology14_exact_matchgate_rational.json`, generated by
`topology14_exact_matchgate_candidate.py`. It keeps the six-CX prefix and local
frames. The first two F blocks have `(a,b)=(pi/4,pi/8)`; the last two are
sqrt-iSWAP blocks. The source hash and grouped ranges are stored with the JSON.

This is the explicit hybrid gate set `{CX, independently tunable F(a,b),
arbitrary one-qubit gates}`: 10 two-qubit gates, dependency depth 8, and
compiled CNOT bound 14. It is not a circuit over fixed sqrt-iSWAP alone. In
particular, one exchange `E(t)=F(t,t)` cannot directly replace the unequal-angle
first blocks. An algebraic handoff gives
`F(a,b)=E((a+b)/2) X_c E((a-b)/2) X_c`; this suggests a 12-gate hybrid
CX-plus-variable-exchange construction, but that variant is not saved or
certified here. Uniform native-gate compilation is a separate follow-up.

Run from the repository root:

```bash
python3 -m unittest test_native_gate_check -v
python3 native_gate_check.py collaboration/native_baseline.json --reference topology14_exact_matchgate_rational.json
```

The initial rerun gave native-to-compiled error `8.46e-16`, right-cycle
 off-diagonal error `4.01e-16`, and unitary error `1.11e-15`. The tests cover
both reversed/nonadjacent embeddings, the two-CX F identity at unequal and
generic angles, fixed exchange signs, CP compilation phase, malformed inputs,
parallel depth, and a changed baseline angle that breaks diagonalization.
